# blinkpip 확장 (시험판 0.5.0)

Chrome/Edge 116+ 확장. 영상 위에 마우스를 올리면 PiP 버튼과 **앱으로** 버튼이 뜬다. iframe 안에서는 지원하지 않는 PiP+ 버튼을 숨긴다.

| 버튼 / 단축키 | 방식 | 타이틀바 | 재생 줄 | DRM(Netflix 등) |
| --- | --- | --- | --- | --- |
| **PiP+** / `Alt+Shift+P` | Document PiP: 사이트의 `<video>`를 창으로 옮기고 아래에 재생 줄·자막을 둔다 | 있음(크롬이 그림, 제거 불가) | 창 안에 있음 | 이론상 가능(사이트별 시험 필요) |
| **무테** / `Alt+Shift+O` | 기본 영상 PiP: 영상+자막을 캔버스에 합성해 띄운다 + **컨트롤 창**을 따로 연다 | **영상 창은 없음** | 별도 컨트롤 창 | **불가**(캔버스에 검게 나옴) |

## 앱으로 보내기

1. 설치된 blinkpip 앱에서 **설정 → 북마크·정보 → 확장에서 앱으로 열기 → 확장 연결 등록**을 한 번 실행한다.
2. 원하는 영상 위의 **앱으로**, 또는 PiP+ 재생 줄의 **앱으로**를 누른다. iframe 안에서도 누른 영상과 그 프레임의 주소를 사용한다.
3. 미리보기에서 **보던 위치**(기본 선택), **자막 파일 주소**, **재생 속도**, **PIP로 바로 시작**을 고른 뒤 **앱에서 열기**를 누른다. 마지막 클릭 때 현재 위치·속도·주소를 다시 확인한다. 주소가 바뀌면 확인 후 한 번 더 눌러야 한다.

`hybridpip://play?v=1&url=...` 링크로 설치된 앱을 연다. 브라우저가 외부 앱 실행 확인을 표시할 수 있다. 앱 설치 여부나 실행 성공을 확장이 직접 확인할 수 없으므로 응답이 없으면 앱의 확장 연결 등록을 확인한다. 원래 영상은 계속 재생된다.

직접 재생 가능한 HTTP(S) 영상 주소를 우선 사용하고, blob·MediaSource·보호 영상은 안전하게 전달할 수 있는 현재 프레임의 페이지 주소를 사용한다. YouTube는 공개 영상 페이지 주소를 사용한다. 로그인·DRM이 필요한 페이지의 앱 재생은 보장하지 않는다. 자막은 선택된 표준 `<track>`의 공개 외부 주소만 보낸다. DOM 자막 내용, blob 자막, 로그인·서명이 필요한 자막 주소는 보내지 않는다.

쿠키·인증 헤더·저장소·referrer는 읽거나 전달하지 않는다. URL의 사용자 정보, 인증·서명 쿼리, 조각(`#`), 잘못된 문자·인코딩은 거부한다. 영상/자막 주소는 각각 UTF-8 4,096바이트, 전체 링크는 16,384바이트 이하다. 시간은 0~31,536,000초, 속도는 0.25~4배다. 원래 URL에 있는 `%`를 포함해 각 쿼리 값은 한 번 인코딩한다.

최종 클릭의 실제 링크 이동을 사용하므로 새 확장 권한이나 background 메시지 경로가 필요 없다. 기존 `storage` 권한과 PiP 동작을 유지한다.

## 원본 PiP 모드 (다른 출처 영상·DRM용)

무테는 영상을 캔버스에 합성하므로 **다른 출처의 직접 파일 영상**(예: nooo38의 ArtPlayer가 CDN 파일을 바로 재생)은 캔버스가 오염되어 못 쓴다. 이때 무테가 **자동으로 원본 PiP 모드로 넘어간다.** 이 모드는 합성 없이 실제 영상 요소에 `video.requestPictureInPicture()`를 부른다(사이트 내장 `PIP Mode` 버튼과 같은 방식). 출처·DRM과 상관없이 되고, 한 번 합성이 막힌 영상은 다음부터 바로 원본 PiP로 연다. `Alt+Shift+N`으로 처음부터 이 모드로 열 수도 있다.
영상 위에 자막을 그릴 수 없어서 자막은 컨트롤 창의 자막 칸이 항상 보여 준다(자막 위치 설정이 `영상 위`여도). 컨트롤 창과 영상 조작은 무테와 같다.

## 무테와 컨트롤 창

기본 영상 PiP 창에는 HTML을 넣을 수 없어서, 재생 줄·설정은 **확장 팝업 창(`controls.html`)** 이 맡는다. `무테`를 누르면 background가 이 창을 연다(창 열기는 클릭 허가가 필요 없다). 컨트롤 창은 원래 탭의 영상에 메시지로 명령을 보내고(`chrome.tabs.sendMessage`), 영상 쪽이 상태를 초당 4번 밀어 준다. 무테를 닫거나 탭이 닫히면 컨트롤 창도 닫힌다.

**자막 위치**(설정)가 무테의 자막 표시를 정한다. `영상 아래`(기본)면 영상에는 그리지 않고 컨트롤 창의 자막 칸에 보인다(칸 높이 = 줄 수 × 글자 크기, 창 높이도 내용에 맞게 조절). `영상 위`면 영상 안에 합성하고 컨트롤 창의 자막 칸은 숨긴다. 자막 줄은 영상 쪽이 바뀔 때마다 컨트롤 창으로 보낸다.

**크롬은 PiP 창을 종류와 상관없이 하나만 허용한다.** 무테가 떠 있는 동안 Document PiP를 열면 무테가 닫힌다. 그래서 컨트롤 창을 Document PiP로 만들 수 없고, 일반 팝업 창을 쓴다. 팝업 창은 "항상 위"가 안 되어 다른 창에 가려질 수 있다.

## 설치

1. `chrome://extensions` 또는 `edge://extensions` → 개발자 모드 → "압축 해제된 확장 프로그램을 로드" → 이 `extension` 폴더
2. 코드를 고친 뒤에는 카드의 새로고침(↻)과 시험 탭의 Ctrl+Shift+R이 모두 필요하다. 이미 열린 탭에는 옛 스크립트가 남는다. 파일이 늘면 제거 후 다시 로드한다.

## 설정

툴바의 확장 아이콘(팝업, 타이틀바 없음), PiP+ 창의 `자막` 버튼, 컨트롤 창 아래. 항목은 `settings-fields.js` 한 곳에서 정의해 셋이 같이 쓴다. 저장은 `chrome.storage.local`(바뀐 키만).

글꼴, 글자 크기, 자막 줄 수(1~5), 배경 불투명도(0=투명), 외곽선, 자막 위치(영상 아래/영상 위), 건너뛰기 초.

## 자막 동작

- 표준 `<track>`(TextTrack)이 있으면 현재 큐를 그대로 쓴다.
- 없으면 사이트 DOM(YouTube, Netflix, video.js, JW Player, ArtPlayer, Disney+)을 읽는다.
- 위에서부터 부분 갱신되는 롤업 자막은 바뀌는 중간 상태를 건너뛰고 새로 나타난 줄만 아래에 이어 붙인다(`makeSubFeed`).
- 자막이 이상하면 콘솔에서 `localStorage.hppDebug='1'` 실행 후 새로고침하면 YouTube 자막 DOM 구조가 `[Hybrid PiP][자막 DOM]`으로 찍힌다.

## 알려진 한계

- **iframe 안의 플레이어(내장 플레이어)에서는 PiP+가 안 된다.** Document PiP는 최상위 페이지에서만 열 수 있다(`Opening a PiP window is only allowed from a top-level browsing context`, 실제 사이트에서 확인). 이런 영상에서는 `PiP+` 버튼을 숨기고 `무테`와 `앱으로`를 보여 준다. 무테는 기본 영상 PiP라 iframe 안에서도 되고, 컨트롤 창도 그 iframe을 가리켜 연다(`frameId`).
- 무테 영상 창에는 UI를 못 넣는다(크롬 기본 버튼만). 컨트롤 창은 일반 팝업이라 "항상 위"가 안 된다.
- 무테는 열려 있는 동안 사이트의 탐색(`seekbackward/forward`) 미디어 키 처리를 덮어쓰고, 닫을 때 복원이 아니라 삭제한다(API에 조회·복원이 없다).
- 무테는 다른 출처 영상(CORS 없는 직접 mp4)이면 캔버스가 오염되어 합성할 수 없다. 감지하면 원본 PiP 모드로 넘어간다. DRM 영상은 오염 예외 없이 검게 나와서 감지하지 못한다. 그런 영상은 `Alt+Shift+N`(원본 PiP)을 쓴다.
- 무테의 그림 갱신 타이머는 원래 탭이 가려지면 느려질 수 있다(소리가 나는 탭은 면제). 미확인.
- 2틱(약 0.2초)보다 짧게 스치는 롤업 자막 큐는 안정화 규칙 때문에 건너뛴다.
- 여러 플레이어가 있는 페이지에서는 다른 플레이어의 자막 DOM이 섞일 수 있다.
- Firefox는 Document PiP가 없어 PiP+가 안 된다.
